# Argus — Threat Model

> **Status: pre-release.** Roadmap steps S0 to S7 are implemented on `main`; nothing is published
> to npm yet (see [`ROADMAP.md`](../ROADMAP.md)). This document is the security design the code is
> held to. Each row is marked:
>
> - **Enforced today**: the code does what the row says, and a named test in this repository fails
>   if it stops doing so.
> - **Partly enforced**: the code does part of it; the gap is stated in the row as a residual risk.
> - **Documented limit**: Argus does not do this, and the docs say so.
>
> It never claims that untested or unbuilt code is secure. What Argus does _not_ guarantee is in
> [`LIMITS.md`](./LIMITS.md); how to report a problem is in [`SECURITY.md`](../SECURITY.md).

Argus runs **inside** the Node.js process it observes and serves what it sees to a browser. That
combination decides everything here: a flaw in Argus is a flaw in the host process, and anything
the dashboard shows is data an attacker would like.

## 1. Trust assumptions

- **Trusted:** the operator who installs and configures Argus, and the host application's own code.
  Argus does not defend the host from itself or from an operator who chooses to expose the dashboard.
- **Not trusted:** anything that reaches the dashboard over the network; **plugin rules** (user
  supplied code); **heap snapshots, profiles and stack traces** handed to the analyzer; the content
  of the host's requests (URLs, headers, payloads) that Argus records; the endpoints that webhooks
  and OpenTelemetry export talk to; and every dependency, build step and release artifact in the
  supply chain.
- **Out of scope:** an attacker who can already run code inside the host process (they can do
  anything Argus can), and physical access to the machine.

## 2. Surfaces, threats and mitigations

| A1  | Agent in the host process                      | Argus crashes, stalls or leaks memory in production                                             | Hooks, observers and the sampler tick catch their own errors and report them once (an `[argus]` line on stderr or a process warning); they never throw into the host. Prototype wrappers stay pass-through after `disable()` when another wrapper sits on top, and are shared between an ESM and a CJS copy (`prototype-patch-safety.test.ts`, `prototype-patch.integration.test.ts`, `sampler-controller-tick.test.ts`). Every agent buffer is bounded and drops the oldest entry, with the loss counted on every sample line (`export-loss.test.ts`, `ndjson-export.ac2.test.ts`). **Residual:** overhead is measured by `bench/overhead.mjs` nightly but not gated.                                                                                                                              | Partly enforced  |
| A2  | Agent in the host process                      | A dependency of Argus compromises every host that loads it                                      | The agent imports only `node:` builtins and its own files, and the root package has no runtime `dependencies`. | B1  | Dashboard and SSE endpoint                     | Unauthenticated access to runtime internals                                                     | The caller chooses the bind address. Binding anything other than a loopback address without a token is refused at startup. Tokens and session cookies are compared in constant time over fixed-length digests (`dashboard-sse-server.ac2.integration.test.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Enforced today   |
| B2  | Dashboard and SSE endpoint                     | A web page the operator visits attacks the local dashboard (DNS rebinding, cross-site requests) | Every request's `Host` must be the bind address on the bound port (plus `localhost`, `127.0.0.1` and `[::1]` for a loopback or any-address bind, plus `allowedHosts`), otherwise `421`. A cross-origin `Origin` on `/events` or on any non-GET request gets `403`. No CORS headers are sent. There are no state-changing endpoints (`dashboard-security.integration.test.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                      | Enforced today   |
| B3  | Dashboard and SSE endpoint                     | The token leaks through URLs, logs or `Referer`                                                 | `?token=` is accepted only on `GET /` and is exchanged for an `HttpOnly`, `SameSite=Strict` cookie (an HMAC of the token under a per-server random key, not the token) with a `303` to `/`. Assets and `/events` accept the cookie or `Authorization: Bearer`, and reject `?token=`. Served HTML and JS contain no token. Every response sets `Referrer-Policy: no-referrer`. Argus never logs the token (`dashboard-security.integration.test.ts`). **Residual:** the cookie cannot be revoked on its own; change the token or restart the server.                                                                                                                                                                                                                                                 | Enforced today   |
| B4  | Dashboard and SSE endpoint                     | Traffic read or altered on the network                                                          | Argus does not terminate TLS. Remote access goes through an authenticated tunnel or a reverse proxy; the docs say so. See `LIMITS.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Documented limit |
| C1  | Collected data (traces, URLs, headers)         | Secrets and personal data end up on the dashboard, on disk or in an alert                       | Capture is fixed, not filtered: a span holds trace and span ids, method, the path with its query string removed, status code and timing. No header, cookie, body or query value is captured anywhere in the pipeline, so no sink can receive one (`trace-context.ac3.integration.test.ts` and `span-export-wiring.ac1.integration.test.ts` assert the query is stripped). **Residual:** a secret inside a path segment (for example `/reset/<token>`) is recorded as is.                                                                                                                                                                                                                                                                                                                            | Enforced today   |
| C2  | Heap snapshots                                 | A snapshot contains whatever was in memory (keys, tokens, user data)                            | Snapshots are taken only when host code calls `takeHeapSnapshot()`; no dashboard or network endpoint takes one. Nothing in Argus sends a snapshot to an alert sink, the dashboard or OpenTelemetry. Node writes the file with mode `0600`. **Residual:** this holds by construction; no test checks the file mode.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Partly enforced  |
| D1  | Plugin runner                                  | A rule escapes its sandbox or reads host state                                                  | Rules run in `isolated-vm`, in a forked child process, with no host references and no `require`. They receive copies of aggregated windows only. `loadRulesDirectory` reads rules from a local directory, never from the network. Rule files are never evaluated in the host (`plugin-runner-sandbox.ac1.integration.test.ts`, `plugin-runner-rule-library.ac3.integration.test.ts`).                                                                                                                                                                                                                                                                                                                                                                                                               | Enforced today   |
| D2  | Plugin runner                                  | A rule exhausts memory or never returns, or floods the host with its result                     | Every run has an isolate memory limit and a wall-clock timeout that the rule cannot raise, backed by a watchdog that kills the child. Results are capped in the child (`maxFindings`, default 10 000; `maxResultBytes`, default 1 MiB) and their shape and size re-checked on the host; error messages are cut to 4 096 characters. Failures come back as typed codes (`ARGUS_RULE_TIMEOUT`, `ARGUS_RULE_MEMORY_LIMIT`, `ARGUS_RULE_INVALID_RESULT`) and are never swallowed (`plugin-runner-sandbox.ac2.integration.test.ts`, `plugin-runner-caps.integration.test.ts`). **Residual:** a failing rule is not disabled; the caller decides whether to run it again.                                                                                                                                 | Partly enforced  |
| E1  | Analyzer (heap snapshots, stack symbolization) | A crafted snapshot or trace exhausts memory or CPU                                              | Parsing runs only in Worker Threads, never on the calling event loop. Every pool worker runs with `resourceLimits` (default 512 MiB old / 64 MiB young generation) and a task timeout (default 30 s). A snapshot file larger than `maxSnapshotBytes` (default 256 MiB) is rejected with `HeapSnapshotTooLargeError` before it is read. The snapshot worker streams the file in small allocations, so hitting the memory limit fails the job and the pool replaces the worker. Source files and maps are capped by `maxFileBytes` (default 64 MiB). No `eval` and no inline workers (`analyzer-containment.integration.test.ts`, run in a child process). **Residual:** `resourceLimits` is best-effort for custom worker files that make one large native allocation (`JSON.parse` of a big input). | Enforced today   |
| E2  | Analyzer                                       | Source-map or symbol lookup reads files it should not                                           | With the `roots` option, every built file and source map is resolved with `realpath` and read only if it lies inside a configured root; `..` and symlink escapes are left unsymbolized. Parse errors use fixed reasons and never quote file content (`stack-symbolization-roots.integration.test.ts`). **Residual:** `roots` is opt-in; without it, any local file a frame or `sourceMappingURL` names can be read. Frames come from the host, not from the network.                                                                                                                                                                                                                                                                                                                                | Partly enforced  |
| E3  | `--trace-deopt` parsing                        | Malformed or oversized lines break the parser or grow memory                                    | `createDeoptParser` treats lines purely as data and never throws. Lines over `maxLineLength` (default 16 384) are not parsed; unparseable lines are counted; retained events are a ring of `maxEvents` (default 1000) with the evictions counted (`deopt-parsing.bounded.test.ts`). GC data comes from `PerformanceObserver` entries, not from parsing `--trace-gc` text. Argus does not capture `--trace-deopt` output itself.                                                                                                                                                                                                                                                                                                                                                                     | Enforced today   |
| F1  | Persistence and output files                   | Path traversal, world-readable files, unbounded disk growth                                     | Opt-in only. The path comes from configuration, never from request data. The window store, the file alert sink and the agent's NDJSON output file create new files with mode `0600`; existing files keep their mode. The window store appends and, past `maxBytes`, compacts to the newest `capacity` windows; after `collector.close()` it never reopens the file (`collector-bounds.integration.test.ts`, `agent-loss-config.integration.test.ts`). **Residual:** Argus does not create or check a `0700` directory, and does not rotate files; the agent's NDJSON output file has no size cap.                                                                                                                                                                                                   | Partly enforced  |
| F2  | Alert webhooks and OpenTelemetry export        | Data leaves the process without the operator realizing, or a hung endpoint stalls the host      | Both are opt-in and off by default. The webhook sends alert JSON; the OTLP exporters send windows as metrics and spans as traces. Requests use Node core `fetch` with a timeout and `redirect: 'manual'`: a 3xx is a failed delivery and the target is never contacted. At most 64 KiB of a response body is read. `close()` is bounded by `closeTimeoutMs`; batches still queued are dropped and counted (`collector-bounds.integration.test.ts`, `otlp-bounds.integration.test.ts`).                                                                                                                                                                                                                                                                                                              | Enforced today   |
| G1  | Supply chain and releases                      | A malicious or tampered release, workflow or dependency                                         | GitHub Actions are pinned to commit SHAs, and CI fails on an unpinned action. Releases publish through npm Trusted Publishing with provenance, from a job that installs nothing; the job that builds holds no publish rights. CodeQL and a pinned, checksum-verified gitleaks scan every change. `npm run check:package` fails the build if a test fixture, a source file or anything outside `dist/` ships.                                                                                                                                                                                                                                                                                                                                                                                        | Enforced today   |

## 3. Named residual risks

These are accepted, not hidden:

1. **`isolated-vm` is defense in depth, not an absolute boundary.** It is a native addon over V8; a
   V8 or addon vulnerability could break isolation. Argus limits what a rule can reach and how much
   it can consume, and treats a rule as untrusted regardless.
2. **Paths are recorded as sent.** Argus captures no headers or query values, but a secret placed
   in a URL path segment reaches every sink.
3. **The agent shares a process with the host.** A fault in Argus is a fault in the application, and
   an attacker with code execution in the host can read or alter Argus's data.
4. **The token gate is access control, not transport security** (B4). The session cookie is valid
   until the token changes or the dashboard server restarts.
5. **Worker memory limits are best-effort.** V8 cannot interrupt one large native allocation; a
   custom worker file that parses a large input in one call can still abort the process. The
   analyzer's own workers avoid this (E1).
6. **The symbolizer is unconfined by default** (E2). Pass `roots` when frames may come from
   anywhere other than your own build.
7. **The number of SSE clients is not capped.** Each client's queue is bounded, but the server
   accepts as many authenticated connections as the operating system allows.
8. **Provenance shows where a package was built, not that its source is benign.** The publish
   pipeline narrows the window for tampering (the tarball is built in an unprivileged job) but a
   compromised dev dependency there could still alter the package contents.

## 4. Keeping this document honest

When a feature from the table ships, its tests must demonstrate the mitigation, and its status
changes to **Enforced today** in the same pull request. A new surface (a new network listener, a
new place data is written or sent, new parsing of untrusted input) needs a new row before it merges.
